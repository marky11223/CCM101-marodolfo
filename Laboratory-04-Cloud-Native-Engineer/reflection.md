# Mission Reflection

This activity helped me understand why Docker containers are useful for modern cloud-native applications. Compared with installing an operating system on a Virtual Machine, a Docker container can start much faster because it does not need to boot a complete guest operating system. This makes the setup process quicker and can reduce the amount of system resources required. I also learned the purpose of port mapping through `-p 8080:80`. Port 8080 is exposed on the host machine and connected to port 80 inside the container, where the Nginx web server is running, so the service can be accessed through the host. Another important lesson was what happens when `docker rm` is used. The command removes the container and its writable layer, so data that exists only inside that container can be lost. This is why important data should be stored using persistent storage when it needs to remain after the container is removed. Containerization also changes the way developers and IT operations teams work together. Applications can be packaged with their dependencies and moved between environments more consistently, which supports DevOps by making development, testing, deployment, and operations more connected and repeatable. The activity showed me that developers and operations teams can work with a more standardized deployment process instead of maintaining completely different environments. My GitHub Cloud Computing Portfolio is also improving because this laboratory adds practical experience with Docker, Nginx, port mapping, and container lifecycle management. Along with the previous laboratories, it gives me more evidence of both cloud concepts and hands-on technical skills. Overall, this mission improved my understanding of how containers can make application deployment faster, more consistent, and more efficient while encouraging better collaboration between development and IT operations teams.
