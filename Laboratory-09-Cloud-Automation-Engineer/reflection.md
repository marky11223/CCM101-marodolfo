# Mission Reflection

Automation is important when managing hundreds of cloud servers because repeating tasks manually takes time and can lead to inconsistent results. A tested script and schedule can perform routine work, such as backups, more consistently and reduce the chance that an administrator forgets a task. However, automation also creates risks. If a script contains a destructive typo and runs across 1,000 servers, it could damage or delete data on many systems before anyone notices. Scripts should be reviewed, tested in a safe environment, protected with appropriate permissions, and monitored before being used at scale.

Writing a Bash script felt different from creating a Docker Compose YAML file in Mission 6. A Bash script contains commands and logic that execute step by step in a shell, while a Docker Compose YAML file describes services and configuration for Docker to run. Both reduce manual work, but they automate different parts of cloud operations. This mission also showed me how to create a compressed backup and schedule it with cron.
