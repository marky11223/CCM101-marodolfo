# Mission 8 Reflection

This mission helped me understand that a host-based firewall provides another layer of protection even if the physical or network perimeter is breached. The firewall runs on the server itself, so it can control which incoming connections are allowed to reach that particular machine. This means the server can still deny unwanted traffic instead of depending only on the network firewall. Managing open ports is also important because every unnecessary port or running service can create another possible entry point for attackers. By allowing only the connections required for the server's purpose, the attack surface becomes smaller and the system is easier to manage securely.

Leaving a database port such as 3306 publicly accessible is dangerous because people outside the trusted network may be able to reach the database service. If the service is misconfigured, vulnerable, or protected by weak credentials, attackers may attempt unauthorized access and could expose or damage important data. Database access should therefore be restricted to the application servers or administrators that actually need it, rather than being open to everyone on the internet.

Before completing this mission, I did not fully appreciate how easily a server's security could be affected by a few open ports or incorrect firewall settings. Configuring UFW showed me why it is important to use a Default Deny policy, allow only necessary traffic such as SSH and the web application's port, and verify the active rules instead of assuming that the configuration worked. I also learned that SSH must be allowed before enabling the firewall to avoid losing remote administrative access.
