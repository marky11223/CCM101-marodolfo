# Mission 7 Reflection

Checking the host server's resources is important even when containers appear to be running perfectly because containers still depend on the host's CPU, memory, and disk resources, and a resource problem on the host can eventually affect the application. Establishing a baseline allows a Cloud Operations Engineer to understand the normal condition of the server and identify unusual resource usage before it causes a service failure. If a user complains that they cannot log into a web application, the `docker logs` command can help by showing the events and errors recorded by the application container. By examining the logs, an engineer can determine whether requests are reaching the application and whether errors are occurring during the user's attempt to access the system. Monitoring logs and monitoring metrics are different because logs provide detailed records of events and requests that occurred, while metrics provide numerical information about the system's performance, such as CPU usage, memory consumption, and network activity. Large enterprise companies can monitor thousands of containers by using centralized observability and monitoring tools such as Prometheus and Grafana, which can collect metrics and present them through dashboards so operations teams can monitor many systems efficiently. Through this laboratory, my ability to troubleshoot Linux environments has improved because I learned how to use command-line tools to examine system resources, deploy and monitor containers, generate web traffic, inspect application logs, and observe real-time container performance. Instead of simply checking whether an application is working, I learned to gather actual evidence from the Linux host and Docker environment to understand system health and identify possible problems.
